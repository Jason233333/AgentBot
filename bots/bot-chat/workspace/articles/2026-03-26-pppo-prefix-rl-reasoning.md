# 开头写好，推理就对了一半：PPPO 如何用前缀优化让 LLM 学会「好好开头」

> 论文：Well Begun, Half Done: Reinforcement Learning with Prefix Optimization for LLM Reasoning
>
> 作者：Yiliu Sun, Zicheng Zhao, Yang Wei, Yanfang Zhang, Chen Gong
>
> 发表：AAAI 2026
>
> 链接：https://arxiv.org/abs/2512.15274

## 一句话总结

只优化模型输出的前 15%-35% 的 token，就能比优化全部 token 多涨 18% 准确率——因为 LLM 推理的「开头」决定了一切。

## 问题与动机

自从 DeepSeek R1 和 OpenAI o1 火了之后，「用强化学习训练 LLM 推理能力」成了最热的方向。这类方法有个统一的名字叫 RLVR（Reinforcement Learning with Verifiable Rewards）——简单说就是让模型做题，做对了给奖励，做错了扣分，靠这个信号来优化模型。

GRPO、DAPO 这些方法的训练方式都一样：模型吐出一长串推理 token，然后对**所有 token** 一视同仁地算梯度、做更新。但问题来了——这些 token 的重要性一样吗？

想想你自己做数学题的经验。如果一开始就选错了思路，比如用了错误的公式、做了不必要的单位换算、或者一上来就截断了小数精度，后面写再多步骤也很难救回来。你可能会说"我可以反思啊"，但实际上人在错误路径上走远了之后，回头的概率非常低。

LLM 也是一样。这篇论文的作者做了一个很精彩的实验来验证这一点：他们从 DeepSeek-R1-Distill 系列模型的正确答案和错误答案中分别提取前 15% 的 token 作为前缀，然后让模型从这些前缀继续推理。结果非常惊人——从正确答案的前缀出发，准确率最多能提高 20.2%；从错误答案的前缀出发，准确率最多暴跌 27.5%。

更绝的是，他们还试了在错误前缀后面加上 "wait" 和 "however" 来触发模型反思（这是目前很流行的一个技巧），结果最多只能恢复 9.2% 的准确率。也就是说，一旦开头歪了，模型基本上就「锁死」在错误路径上了。

作者把这个现象叫做 **Beginning Lock-in Effect（BLE，开头锁定效应）**，灵感来源于经济学和认知科学中经典的 **Path Dependence（路径依赖）** 理论。

既然开头这么重要，那为什么还要在所有 token 上均匀地花训练资源呢？

## 方法详解

基于 BLE 的发现，作者提出了 **PPPO（Progressive Prefix-token Policy Optimization，渐进式前缀 token 策略优化）**。核心思想极其简洁：**只对模型输出的前一小段 token 计算梯度，后面的 token 全部 mask 掉。**

你可能觉得这听起来太简单了。但魔鬼在细节里——直接把后面的梯度砍掉会带来两个问题：

1. 前缀太短的时候，模型还没展开推理，能学到的东西有限
2. 一段前缀到底好不好，单看一次后续推理的结果可能有很大随机性

PPPO 用两个精巧的策略解决了这两个问题。

### 策略一：Progressive Prefix Retention（渐进式前缀保留）

不是一上来就固定保留前 35% 的 token，而是从 15% 开始，逐步增加到 35%。什么时候增加呢？当验证集上的准确率不再提升的时候。

为什么是 15% 和 35%？这两个数字不是拍脑袋定的。作者的实验（Figure 2b）显示：当前缀长度达到 15% 时，BLE 开始显著出现（也就是前缀质量开始明显影响最终结果）；到 35% 时，这个效应基本稳定了。每次增加 5 个百分点，从 15% → 20% → 25% → 30% → 35%。

这个由简到难的课程学习策略很直觉：先教模型学会「怎么开好头」（短前缀），等它学会了这个基本功，再让它学「怎么在好的开头之后继续推进」（长前缀）。

### 策略二：Continuation Accumulated Reward（续写累积奖励）

传统 RLVR 的奖励信号是：模型写完一整个答案，对了给 1 分，错了给 0 分。但在 PPPO 里，我们只优化前缀部分，那怎么评价一段前缀的质量呢？

如果只看「这段前缀后面跟着的那一次完整推理」对不对，随机性太大了。同一个前缀，后面的推理可能有时候对、有时候错。

PPPO 的做法是：对于每一段前缀，让模型从它出发**续写 8 次**，看这 8 次里有几次答对了，答对的次数就是这段前缀的奖励分数。再加上原始那次完整输出的结果，总分最高是 9 分。

这个设计非常合理——如果一段前缀能让模型在 8 次续写里答对 7 次，说明这是个高质量的开头；如果只答对 1 次，说明这个开头虽然碰巧蒙对了一次，但本质上并不靠谱。

### 整体训练流程

把这些拼在一起，PPPO 的训练流程是：

1. 对每个问题，从当前模型采样 8 个完整输出
2. 取每个输出的前 η%（初始 15%）作为前缀
3. 从每个前缀出发，再采样 8 个续写
4. 用续写的累积正确率作为这个前缀的奖励
5. 只对前缀部分的 token 算梯度、做策略更新
6. 当验证集准确率停滞时，把 η 增加 5%

优化目标本身基于 DAPO 的 clipped objective（和 PPO 类似的裁剪策略），只不过多了一个 mask 函数 H(j, o_i)，它在 token 位置 j 超过前缀长度时返回 0。

每个训练步的总采样量是 8×8=64，和 baseline 方法的 64 次采样一样，所以训练成本基本持平。但实际参与梯度计算的 token 只有全部的 15%-35%——也就是说，PPPO 只用了不到三分之一的训练 token 就实现了更好的效果。

## 实验分析

### 实验设置

作者用了 Qwen3 系列三个大小的模型：Qwen3-1.7B、Qwen3-4B、Qwen3-8B，全部开启 thinking mode。训练集是 DAPO-Math-17K。

评测在 5 个推理 benchmark 上进行：AIME'24（美国数学邀请赛 2024）、AIME'25（2025）、MATH 500、AMC'23（美国数学竞赛 2023）、GPQA Diamond（研究生级别的科学问答）。每个数据集测 32 次取平均（avg@32）。

对比的 baseline 包括：原始 backbone 模型、GRPO、DAPO、INTUITOR（用语义熵做奖励的方法）、DAPO-FT（只优化 forking token 即高熵 token 的方法）。

### 主要结果

以 Qwen3-8B 为例（其他模型趋势类似）：

在 AIME'25 这个最难的 benchmark 上，PPPO 比 DAPO 提升了 **18.02%**（绝对值）。这个提升幅度是非常夸张的，意味着模型在竞赛级数学题上的能力有了质的飞跃。

跨所有 5 个 benchmark 的平均准确率，PPPO 比最强的 baseline 提升了 **14.64%**。而且 PPPO 是在所有 benchmark 上都赢，不存在"某个数据集上涨、另一个数据集上跌"的情况。

更有趣的是效率指标：PPPO 训练的模型，推理时输出的 token 数量减少了最多 **18.35%**。也就是说，模型不仅答得更准，还答得更简洁了。这很合理——如果开头就走对了路，后面就不需要反复纠结、绕弯子。

特别值得注意的是和 DAPO-FT 的对比。DAPO-FT 也是一种「不优化所有 token」的方法，它选择只优化高熵 token（比如 "wait"、"however" 这些表示犹豫/反思的词）。但 DAPO-FT 的效果不如 PPPO，而且不稳定。这说明「优化反思能力」不如「优化起手能力」——与其教模型怎么在走错路之后纠正，不如教模型一开始就走对路。

### 消融实验

作者做了非常详细的消融：

1. **去掉渐进式策略，固定 η=15%**：性能下降明显。说明随着训练推进，逐步增加前缀长度是有必要的。

2. **去掉续写累积奖励，改用单次奖励**：性能也下降了。说明多次续写带来的稳定奖励信号确实比单次采样更可靠。

3. **不同初始 η 的影响**：从 5%、10%、15%、20%、25% 开始都试了，15% 是最优起点。太短（5%）的前缀信息量不够；太长（25%）的话一开始学习难度太大。

4. **续写次数 G 的影响**：G=1（没有多次续写）效果最差；G=4 和 G=8 差不多，说明 8 次续写已经足够得到稳定的奖励估计。

## 我的评价

### 亮点

这篇论文最让我欣赏的是它的**洞察力**。BLE（开头锁定效应）这个发现虽然说出来很直觉（"好的开始是成功的一半" 这个道理连小学生都知道），但作者用严谨的实验量化了这个效应，并且围绕它设计了一套完整的训练方法。从发现现象 → 验证现象 → 利用现象 → 设计方法，逻辑链非常漂亮。

另一个亮点是**效率**。PPPO 只用了 26.17% 的训练 token 就超过了用 100% token 训练的方法，这对于实际部署来说非常有吸引力。训练成本降低了但效果更好，这种 "少即是多" 的结果总是最有说服力的。

### 局限性

1. **评测模型偏小**：最大只测到了 Qwen3-8B。在 70B 或更大的模型上，BLE 是否同样明显？更大的模型可能有更强的「自我纠错」能力，前缀的影响可能会减弱。

2. **只测了数学和科学推理**：BLE 在代码生成、逻辑推理、自然语言推理上是否也成立？不同类型的任务，前缀的最优长度可能差异很大。

3. **15% 和 35% 的超参数**：这两个数字是在特定模型和数据集上观察到的。换一个模型/数据集，最优的前缀比例可能完全不同。论文没有给出一个自动确定最优 η 范围的方法。

4. **和 Best-of-N 的比较缺失**：续写 8 次取最好的，听起来和 Best-of-N sampling 有点像。如果在推理时直接多采样几次开头、挑最好的继续，能不能达到类似效果？这个 inference-time 的 baseline 没有比较。

### 影响

这篇论文的核心发现——**LLM 推理过程中前缀 token 的质量决定了整条推理链的走向**——对后续的 RLVR 研究有重要指导意义。它告诉我们，token 不是平等的，不同位置的 token 在训练中应该有不同的权重。这个思路可以扩展到很多方向：比如在推理时动态调整不同位置 token 的采样温度、或者专门训练一个 "开头模型" 和一个 "续写模型" 的协作系统。

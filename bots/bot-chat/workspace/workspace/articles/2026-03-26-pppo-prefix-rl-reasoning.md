# 好的开始是成功的一半：PPPO 用前缀优化重新定义 LLM 推理训练

> 论文：Well Begun, Half Done: Reinforcement Learning with Prefix Optimization for LLM Reasoning
>
> 作者：Yiliu Sun, Zicheng Zhao, Yang Wei, Yanfang Zhang, Chen Gong（南京理工大学）
>
> 发表：AAAI 2026 | arXiv: 2512.15274

---

## 一句话总结

**LLM 推理的「开头」决定了整条推理链的命运。** 只优化输出的前 15%-35% 的 token，比优化全部 token 效果更好、训练更快、输出更短。

---

## 这篇论文解决了什么问题？

当下最火的 LLM 推理训练范式叫 RLVR（Reinforcement Learning with Verifiable Rewards）——DeepSeek R1 和 OpenAI o1 背后的核心技术。GRPO、DAPO 这些方法的思路很直接：让模型生成一堆回答，对的给正奖励、错的给负奖励，然后用 RL 优化所有 token 的策略。

问题是：**不是所有 token 都值得优化。**

一条 10000 token 的推理链里，有些 token 是关键的思路选择（"让我先把这个问题转化为..."），有些只是计算填充（"3×7=21"）。现有方法一视同仁地优化所有 token，大量算力浪费在那些对最终结果影响微乎其微的 token 上。

这篇论文的核心发现是：**推理链的「开头」才是真正的胜负手。**

---

## 核心发现：Beginning Lock-in Effect（开头锁定效应）

这是全文最精彩的部分。作者做了一个非常漂亮的受控实验：

**实验设计：** 用 DeepSeek-R1-Distill-Qwen 系列模型（7B/14B/32B）在 AIME'24 和 GPQA Diamond 上，分别生成 4 条正确和 4 条错误的推理链。然后截取每条推理链的前 15% token 作为固定前缀，让原始模型从这个前缀继续生成 8 次，计算平均准确率。

**结果令人震撼：**

从正确答案的前缀出发推理，准确率最高提升 20.2%；从错误答案的前缀出发推理，准确率最高暴跌 27.5%（AIME'24，DeepSeek-R1-Distill-Qwen-14B）。

**仅仅 15% 的开头 token，就能把最终答案的正确率拉开将近 50 个百分点。**

更关键的是，作者还测试了「自我纠错」的可能性——在错误前缀后面加上 "wait" 和 "however" 这类反思触发词，想看模型能不能自己掰回来。结果是：最多只恢复了 9.2% 的准确率。一旦开头走错了路，模型几乎无法逃脱。

这个现象被命名为 **Beginning Lock-in Effect（BLE，开头锁定效应）**，灵感来自经济学中著名的路径依赖（Path Dependence）理论。

### BLE 的直观理解

想象你在做一道数学题。如果一开始就选了错误的解题策略——比如把角度问题当成了坐标问题来解——那后面不管算得多仔细，大概率也是错的。而且由于 LLM 是自回归生成的（每个 token 都依赖前面所有 token），错误的开头会像滚雪球一样把整条推理链拖进歧途。

论文中的 Figure 1a 给了两个具体例子：一个是在开头做了不必要的小数截断导致精度丢失，另一个是在开头做了多余的单位转换导致复杂度爆炸。两种情况都是「开头的一个小失误，后面一路错到底」。

### BLE 在不同前缀长度下的表现

作者还测试了不同前缀长度（5% 到 50%）对 BLE 的影响。发现 BLE 在前缀比例达到 15% 时就开始显著出现，到 35% 时基本完全建立。也就是说，推理链的前三分之一已经基本锁死了最终结果。

## 方法：Progressive Prefix-token Policy Optimization（PPPO）

既然开头这么重要，那为什么不**只优化开头**呢？这就是 PPPO 的核心思路。

### 整体框架

PPPO 基于 GRPO 框架改造而来。对于每个问题 q，PPPO 先采样 N=8 条完整推理链，然后截取每条链的前 η% token 作为前缀序列。关键改动在于：**只保留前缀 token 的梯度，mask 掉后面所有 token 的梯度。** 用一个简单的指示函数 H(j, o_i) 来实现：当 token 位置 j ≤ ⌊η·|o_i|⌋ 时保留梯度，否则 mask。

这意味着模型依然会生成完整的推理链（用于评估对错），但反向传播时只更新与「如何开始推理」相关的参数。

### 策略一：Progressive Prefix Retention（渐进前缀保留）

直接把 η 设成一个固定值并不是最优的。PPPO 采用了一种课程学习（curriculum learning）的策略：

**η 从 15% 开始，每当验证集准确率停滞不前时，自动增加 5%，直到 35%。**

为什么这样设计？因为较短的前缀更容易学习——模型只需关注「最关键的开头几步」，学习复杂度低。等模型在 15% 的前缀上学到了高质量的推理开头能力后，再逐步扩展到更长的前缀，此时模型已经有了扎实的基础，可以稳定地学习更复杂的内容。

这比直接设 η=35% 的效果更好：平均准确率高 2.19%，同时训练 token 还少了 8.83%。

### 策略二：Continuation Accumulated Reward（续写累积奖励）

传统 RLVR 的奖励信号很简单：答对了给 1 分，答错了给 0 分。但这对前缀优化来说有个问题——**同一个前缀，续写 8 次可能 3 次对 5 次错，那这个前缀到底算好还是坏？**

单次采样的奖励噪声太大了。PPPO 的解决办法是：对每个前缀 b_i，额外采样 G=8 条续写，累加所有续写的正确性作为这个前缀的奖励：

R_i = Σ(续写正确次数) + 原始输出是否正确

这样，一个能引导出 7/8 正确续写的前缀和只能引导出 2/8 正确续写的前缀，会得到截然不同的奖励信号。通过多次采样来平滑奖励，大幅降低了随机性，让策略更新更稳定。

实验表明：从 G=0（单次奖励）增加到 G=8（累积奖励），平均准确率提升高达 8.37%，方差降低了 2.67%。

## 实验结果：全面碾压

### 实验配置

**骨干模型：** Qwen3-1.7B、Qwen3-4B、Qwen3-8B（thinking mode）

**训练数据：** DAPO-Math-17K

**基线方法：** GRPO、DAPO、INTUITOR、DAPO-FT

**评测基准：** AIME'24、AIME'25、MATH 500、AMC'23、GPQA Diamond（avg@32）

### 主实验（Table 1）

PPPO 在 15 个设定（3 个模型 × 5 个基准）中赢了 14 个。唯一输的一个是 Qwen3-1.7B 在 AMC'23 上以 0.14% 的微弱劣势不敌 DAPO——可以忽略不计。

几个亮眼的数字：

**AIME'25 上，Qwen3-8B 的 PPPO 比 GRPO 高出 18.02%，比 DAPO 高出 10.94%。** 这在竞赛数学这种难度上是巨大的提升。

跨所有基准的平均准确率，PPPO 比最强基线高出最多 14.64%。

### 训练效率（Table 2）

这才是最惊人的部分。作者定义了一个 LE（Learning Efficiency）指标 = 平均准确率提升 / 优化 token 比例。PPPO 只优化了 24.83%-26.17% 的 token（因为只算前缀），但准确率提升却最大。也就是说：

**PPPO 用不到四分之一的训练 token，做到了比全 token 训练更好的效果。**

### 推理效率（Figure 4）

更意外的收获：PPPO 训练出的模型，输出长度比其他方法短了最多 18.35%，同时准确率还最高。这说明学会了高质量的推理开头后，模型不需要冗长的试错和自我纠正，可以更简洁地直达正确答案。

### 跨模型泛化（Figure 5）

作者做了一个很巧妙的实验：把 PPPO 训练过的 Qwen3-4B 生成的前缀，喂给完全不同的模型 Qwen2.5-7B-Instruct 来续写。结果表明，PPPO 前缀让 Qwen2.5-7B-Instruct 的准确率提升了最多 9.04%。而未经 PPPO 训练的 Qwen3-4B 前缀，对 Qwen2.5-7B-Instruct 几乎没帮助，甚至在 AIME'25 上还降低了准确率。

这意味着 PPPO 学到的不是 model-specific 的技巧，而是通用的高质量推理开头策略，可以迁移到其他模型上。

### 消融实验（Figure 6）

作者对比了 6 种不同的前缀保留策略：固定 η=15%/20%/25%/30%/35%，以及渐进式 15%→35%。结果很清楚：渐进式策略（也就是 PPPO 采用的）在训练全程都保持最稳定的提升，最终准确率比固定 η=35% 高 2.19%，比最差的固定策略高 12.49%。

## 我的点评

### 值得关注的亮点

**1. BLE 是一个深刻的观察。** 这不是一个显而易见的结论。很多人（包括我）可能直觉上觉得「中间的关键步骤」或者「最后的总结」更重要。但实验数据清楚地表明，开头才是决定性的。这和人类的经验其实很一致——做题时第一步选错了方法，后面再怎么算也白搭。

**2. 方法极其简洁。** PPPO 的核心改动就是一个 mask 函数 H(j, o_i)，加上多次续写求累积奖励。没有引入新的网络结构、没有复杂的训练流程，在任何 RLVR 框架上都可以即插即用。这种 simplicity 是最优雅的。

**3. 效率收益是免费的。** 少优化 75% 的 token 意味着反向传播的计算量大幅减少。同时模型还学会了更短的输出，推理时的 FLOPs 也降低了。训练省、推理也省，一石二鸟。

### 可以思考的问题

**1. BLE 的成因是什么？** 论文观察到了 BLE 的存在，但没有深入解释为什么 LLM 会有如此强烈的路径依赖。这可能和 attention 机制中 early token 的 positional bias 有关，也可能和 softmax 的归纳偏置有关。搞清楚成因，可能打开更大的优化空间。

**2. 和 DAPO-FT（Forking Tokens）的关系。** DAPO-FT 选择优化高熵 token（比如 "wait"、"however" 这些反思词），PPPO 选择优化前缀 token。两者其实在回答同一个问题：哪些 token 值得优化？有没有可能把两者结合——在前缀中找到高熵 token 进行优化？

**3. 长推理 vs 短推理的影响。** 论文用的 backbone 是 Qwen3 thinking mode（长推理），最大输出 10240 token。如果 backbone 是短推理模型（比如 2048 token），BLE 的效应会不会减弱？毕竟短推理链中「开头」占的比例天然就更大。

**4. Continuation Accumulated Reward 的成本。** 每个前缀要额外采样 8 条续写来计算奖励，这意味着 PPPO 的采样成本是标准 GRPO 的 8 倍。虽然反向传播便宜了，但 forward pass 的总计算量其实增加了。论文没有报告端到端的训练 wall time，这是一个重要的缺失。

---

## 总结

这篇论文的核心贡献：

**发现了 BLE：** LLM 推理链的前 15%-35% token 几乎决定了最终结果，且模型极难从错误开头中恢复。

**提出了 PPPO：** 一种只优化前缀 token 的 RLVR 方法，通过渐进式前缀保留和累积奖励两个策略，在 5 个推理基准上全面超越 GRPO/DAPO/INTUITOR/DAPO-FT。

**最大亮点：** 用不到 1/4 的训练 token 获得了最大的准确率提升，同时推理输出长度减少了 18%。

如果你在做 RLVR 相关的工作，这篇论文值得仔细读。BLE 的发现不仅对训练方法有启示，对 inference-time compute（比如 best-of-N 采样时怎么分配 compute budget）也有重要参考价值。
